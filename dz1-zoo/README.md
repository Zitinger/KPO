## Обзор проекта
```txt
src/
  app/                      
    main.py                     # интерфейс командной строки и сборка объекта приложения через DI
  
  di/
    container.py                # минимальный DI-контейнер (singleton)

  domain/                       # интерфейсы и сущности
    i_alive.py                  # interface IAlive 
    i_inventory.py              # interface IInventory 
    i_health_policy.py          # interface IHealthPolicy (здоров/не здоров)
    animal.py                   # class Animal
    herbo.py                    # class Herbo
    predator.py                 # class Predator
    thing.py                    # class Thing
    
  services/                     # сценарии и политики

    zoo_service.py              # ZooService (прием животных, вещи, отчеты)
    random_health_policy.py     # RandomHealthPolicy (определение здоровья животного рандомно)

tests/
  test_domain.py                # тесты для domain
  test_services.py              # тесты для services
```

## Интерфейсы и классы (domain)

### Интерфейсы (на базе ABC):
- ***IAlive*** - описывает живые сущности (имеют свойство *food* - количество еды в день);  
- ***IInventory*** - описывает все, что можно учесть (имеют *number* - инвентарный номер);  
- ***IHealthPolicy*** - описывает определение здоровья *bool is_healthy(animal)*.

### Классы:
- *Animal (IAlive, IInventory)* - базовый класс животного, проверяет имя и количество еды, номер можно задать только один раз;  
- *Herbo (Animal)* - травоядное, добавляет параметр доброты (0..10), если доброта > 5 - животное подходит для контактного зоопарка;  
- *Predator (Animal)* - хищник, просто наследует Animal без изменений;  
- *Thing (IInventory)* - предмет с уникальным названием и номером.  

Интерфейсы задают границы того, что должен уметь объект, а классы реализуют эти правила на практике.

---

## Прикладной уровень (services)

- ***InventoryRegistry*** - выдает инвентарные номера и формирует отчет (номер + название объекта);  
- ***RandomHealthPolicy*** - определяет здоровье животного случайно (90% шанс, что здоров). У каждого животного свой генератор случайных чисел;  
- ***ZooService*** - объединяет все: добавляет животных и предметы, считает корм, отбирает добрых животных и делает отчеты.  

Такое разделение нужно, чтобы код можно было тестировать без участия пользовательского ввода.

---

## Сборка и запуск (DI + пользовательский ввод)

- *container.py* - простой контейнер зависимостей: хранит фабрики и создает объекты один раз (singleton). Это отражает принцип DIP - зависимости передаются извне.  
- *main.py* - точка входа. Здесь создаются объекты (InventoryRegistry, RandomHealthPolicy, ZooService) и запускается консольное меню с командами: добавить животное, добавить предмет, показать отчет, выйти.

## Применение принципов SOLID

### **S - Single Responsibility (единственная ответственность)**  
Каждый класс делает только одну задачу:  
Animal и его наследники - за состояние, Registry - за учет, Policy - за здоровье, ZooService - за операции, main.py - за интерфейс.  

### **O - Open/Closed (открыт для расширения, закрыт для модификации)**  
Можно добавить новые типы животных или правила определения здоровья, не меняя старый код - просто создать новый класс и зарегистрировать его в DI.  

### **L - Liskov Substitution (подстановка Барбары Лисков)**  
Herbo и Predator можно использовать везде, где нужен Animal, без изменений поведения.  

### **I - Interface Segregation (разделение интерфейсов)**  
Интерфейсы маленькие и независимые. Например, Thing реализует только учет, а не жизнь.  

### **D - Dependency Inversion (инверсия зависимостей)**  
ZooService не создает объекты сам - он зависит от абстракции IHealthPolicy. Конкретная реализация подставляется через DI.

## Ключевые идеи

- **Один класс - один файл.** Проект читается проще.  
- **Рандомное здоровье.** Простая демонстрация работы и можно легко подменить логику.  
- **DI-контейнер.** Реализует DIP и делает код гибким.  
- **Простой интерфейс.** Консоль управляет действиями, а вся логика живет в сервисах - тестировать просто.
